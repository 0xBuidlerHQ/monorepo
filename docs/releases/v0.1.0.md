# v0.1.0 — Local alpha

Validation date: November 17, 2026. This records local acceptance testing, not a public deployment or a published Git tag.

## Included scope

- Passkey accounts with Kernel wallets.
- Pokémon discovery, all-generation Pokédex, English Base Set catalogue and printing references.
- Authenticate requests by certifier and certification number; staff review, inspection, and passport issuance.
- Immutable ERC-721 passports, IPFS metadata, independent archives, public verification and history.
- Collection, Passports, Activity, and guided NFT transfers.
- Manual hand-to-hand or delivery returns from TrueOrigin, with separate owner receipt confirmation.
- Shared live search across app pages, Pokémon, collections, cards, and public passports. Search supports names, species/card numbers, illustrators, certification numbers and full item IDs. Keyboard arrows/Enter navigate results; Cmd/Ctrl+K opens the drawer.

Sealed is removed from category navigation while empty. Its previous URL redirects to Catalogue. Marketplace, payments, sale classification, escrow, and peer-to-peer physical handover tracking are excluded.

## Acceptance evidence

The browser acceptance test uses two separate browser contexts and virtual WebAuthn authenticators against the running local stack. It creates clearly labelled test data and leaves the resulting passport on the development chain.

- Two independent passkey accounts obtain different Kernel addresses.
- User A requests authentication; staff accepts, records arrival, inspects, approves, and issues the NFT to A's authenticated wallet.
- Staff records hand-to-hand return; A confirms physical receipt independently from NFT issuance.
- Collection and Verify resolve the issued passport.
- Cancelling a passkey signing request leaves no submitted transfer and permits retry.
- A real passkey-authorized transfer goes from A to B. Delaying receipt responses and refreshing recovers the original pending operation rather than sending again.
- Both Collections, the passport owner, Passports, and Activity reflect the transfer.
- Search finds the issued passport by certification number.

Automated coverage also checks rejected recipients, stale ownership, wrong chain/contract/item identity, reverted operations, receipt timeouts, failed storage before minting, restart reconciliation after a lost RPC response, and duplicate issuance protection. The isolated integration test restores IPFS content from CAR archives and rebuilds public records without the private submission database.

Search interaction checks cover grouped catalogue/species results, keyboard navigation, drawer close on selection, Cmd+K, no matches, rapid query changes, network error recovery, and the Sealed redirect.

## Repeat the checks

Start the local stack yourself with `make dev app.trueorigin.com`. This resets development data. Keep it running while running the browser test in another terminal:

```sh
CHROME_PATH="/absolute/path/to/chrome-or-chromium" node scripts/test-alpha-browser.mjs
```

The browser test is restricted to localhost/127.0.0.1. Optional `APP_URL` and `ADMIN_URL` override ports. Virtual authenticators do not access the operator's actual passkeys. Each run uses a temporary browser profile; the test accounts and passport remain in the local backend until the next development reset.

Other checks, from the repository root:

```sh
pnpm --filter @0xhq/app.trueorigin.com typecheck
pnpm --filter @0xhq/app.trueorigin.com test
pnpm --filter @0xhq/api test
pnpm --filter @0xhq/api test:issuance
pnpm --filter @0xhq/contracts.trueorigin.com test
(cd packages/trueorigin-sdk && node --test src/transfers.test.ts)
```

## Known limitations

- This is a local alpha. Issuance/transfers use chain 31337; `make dev` resets its data. No production deployment or production build certification is included in this validation.
- Browser acceptance used desktop Chromium virtual passkeys. Physical authenticators, mobile browsers, synced-passkey recovery, and cross-device sign-in still need device testing before a pilot.
- Reference coverage is English Base Set. Printing variants reuse the reference image; they are not separate verified scans. No market prices or population data.
- Search returns up to six matches per group for nonempty queries, using text matching rather than fuzzy or semantic search. Only public passports are indexed; private submissions, contact details, and return instructions are excluded. If the public passport service is unavailable, catalogue search remains available with a notice.
- QR scanning reads passport/verification codes; it does not inspect a physical card or perform label OCR.
- NFT ownership is distinct from physical possession. A transfer is not automatically a sale. Physical handover assertions are manual.
- Metadata is immutable. The current contract has no revocation, metadata correction, seizure, or transfer-freeze mechanism.
- Public records can be reconstructed from chain history and retained IPFS content. Private workflows and passkey account records require separate backups.
- A public pilot still requires persistent infrastructure, secured staff/issuer access, monitoring, restore drills, and a decision about recovery and authentication corrections.

## Development seeding — November 19, 2026

`make dev` now seeds eight real local-chain NFTs with immutable metadata and card artwork in local IPFS, twelve private submissions, three indexed NFT transfers, and sample return/receipt records. All certification and inspection claims in this dataset are fictional and marked as development demos in metadata. This supersedes the earlier empty-startup behavior; `TRUEORIGIN_DEV_SEED=false make dev` retains an empty run. The seed uses demo Anvil owners; signed-in Collection ownership is unchanged.

The isolated seed integration test checks real token URIs, IPFS bytes, on-chain owners/history, idempotent reruns, normal workflow records, backup image serving, and the API entrypoint used by development startup. Production and wrong-chain guards are covered by unit tests.
